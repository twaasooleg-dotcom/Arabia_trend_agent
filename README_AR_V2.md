# ArabiaTrend Agent v2 — التشغيل التلقائي وحدود المجانية

هذه حزمة بديلة لمسار التشغيل المحلي السابق، تضيف مزودي API وتوليد الصور ومراجعتها والاستئناف والجدولة. لا تحتاج Ollama أو Qwen Code أثناء التشغيل. يعمل المنسق الخفيف على Windows، بينما تتم معالجة النصوص والصور عند المزودين.

## المتطلبات

Windows بحساب تسجيل دخولك المعتاد، PowerShell، وPython 3.11 أو أحدث مع pip، وإنترنت مستقر. لا حاجة إلى GPU أو تشغيل نموذج محلي. موقع WordPress الحالي يجب أن يسمح REST API ورفع الوسائط، وأن يعمل كرون الخادم. الاستضافة والكهرباء والإنترنت الحاليون خارج معنى تكلفة API الصفرية.

## التثبيت مرة واحدة

1. انتظر انتهاء أي تشغيل قديم. فك محتويات ZIP داخل مجلد مشروعك نفسه: C:\Users\Me\Projects\arabiatrend-agent. لا تحذف state أو .venv أو ملفات اعتماد Windows. أسماء ملفات v2 منفصلة عن agent.py القديم.
2. افتح START.cmd. سيتولى إنشاء البيئة عند الحاجة وتثبيت المكتبات وتشغيل الاختبارات والتحقق من الاتصال ثم تسجيل مهمة Windows كل 15 دقيقة.
3. أدخل المفاتيح محليًا عند السؤال. لا ترسل مفاتيحك إلى المحادثة. تُحفظ مشفرة عبر Windows DPAPI في LocalAppData\ArabiaTrendAgent وتُفك فقط تحت حساب Windows نفسه والجهاز نفسه.
4. بعد READY ستبدأ المهمة تلقائيًا خلال نحو دقيقتين. auto_schedule مفعّل في config-v2.json. يتم استبدال مهمة ArabiaTrend-Tech-Agent التابعة للمشروع فقط.

السكربتات تستخدم ExecutionPolicy Bypass للعملية الخاصة بها لتجنب تكرار تحذير تنزيل الملف؛ لا تعدل سياسة التنفيذ العامة. راجع ملفات الحزمة قبل تشغيل المثبت.

Windows يحتاج تسجيل دخول الحساب وبقاء الجهاز يعمل؛ قفل الشاشة لا يمنع التشغيل. الجهاز المغلق أو تسجيل الخروج يوقف إعداد الأخبار الجديدة. يمكن لWordPress نشر المواد المجدولة مسبقًا والجهاز مغلق بشرط عمل WP-Cron على الخادم. اسأل الاستضافة عن كرون منتظم؛ لا يكفي انخفاض الزيارات لضمان النشر في الدقيقة المحددة.

الحزمة لا تنشر نفسها على Cloudflare Workers، ولا تحتاج اشتراك استضافة جديد. لو أردت إيقاف الكمبيوتر تمامًا فلابد من نقل المنسق لبيئة تعمل دائمًا، مثل VPS موجود بالفعل أو تنفيذ منفصل على Workers ضمن حدوده. امتلاك Cloudflare API لا ينقل سكربت Python إلى السحابة تلقائيًا.

## البيانات التي تدخلها مرة واحدة

| البيان | مكانه والغرض |

| Groq API key | توليد المقال وتصحيحه، على Groq Free |

لا حاجة لمفتاح Cloudflare Global API أو دخول root أو صلاحيات تعديل DNS أو قواعد بيانات WordPress. صلاحيات مستخدم WordPress يجب أن تكفي إنشاء وتعديل ونشر مقالاته ورفع الوسائط. لا تعطه إدارة القوالب والإضافات.

لإدخال مفتاح بديل: أوقف المهمة، احتفظ بالملف المشفر الأصلي كنسخة احتياطية ثم احذف api-secrets-v2.xml وأعد START.cmd. هذا يؤثر على مفاتيح v2 فقط. لا تغير wordpress-credential.xml إلا لتبديل اعتماد الموقع.

## توزيع المهام على المزودين

- Groq: النموذج openai/gpt-oss-120b ككاتب أساسي. النص يأتي من مصدر منشور، وليس من ذاكرة النموذج للأخبار الحديثة.
- Gemini: النموذج gemini-3.8-flash للمراجعة المستقلة نسبيًا، وفحص الصور وكتابة وصفها، وبديل للنص عند فشل Groq. لا يستخدم البرنامج Google Search Grounding ولا نماذج Google لتوليد الصور.
- Cloudflare: @cf/black-forest-labs/flux-2-klein-4b لتوليد الصورة تلقائيًا عبر multipart API، ثم قصها وضغطها إلى 1200×600.
- Ollama: غير مطلوب في v2، لتجنب بطء الجهاز وانقطاعاته التي ظهرت في التجربة السابقة.

المثبت يتحقق من ظهور نموذجي النص في قائمتَي المزودين. فحص القراءة لا يثبت حصة توليد فعلية أو أن الحساب مجاني. أول عملية صور تختبر الوصول إلى Workers AI؛ لم يتم اختبار مفاتيح حسابك داخل هذه المحادثة.

## الحفاظ على المجانية

المعلومات الرسمية المراجعة في 5 نوفمبر 2026:

- Groq Free له حدود طلبات وتوكنات لكل نموذج/منظمة. الجدول الرسمي يعرض لـgpt-oss-120b: 30 طلبًا بالدقيقة، 1000 يوميًا، 8000 توكن بالدقيقة، 200000 يوميًا. صفحة Limits بحسابك هي المرجع الفعلي.
- Cloudflare Workers AI Free يتيح 10000 Neurons يوميًا للحساب. هذا ليس عدد صور. الوصول لما فوقها يحتاج خطة مدفوعة، والخطة المدفوعة تسمح بفوترة الزيادة.
- Gemini API له نماذج نصية مجانية بحصص تختلف حسب المشروع؛ حصصه ليست موحدة لكل المستخدمين. مجانية واجهة AI Studio لا تجعل كل API مجانيًا.
- لا نفترض أن توليد صور Gemini أو Imagen مجاني. الحزمة لا تستدعيهما.
- جمع الأخبار يتم من RSS وصفحات رسمية عامة؛ لا تستخدم الحزمة بحثًا مدفوعًا أو صور Google أو صورًا مجهولة الترخيص. الصور مولدة بدل البحث في مواقع الصور.

الضمان العملي لمنع فاتورة المزود: استخدام حسابات/مشروعات على Free فعلًا دون تفعيل فوترة مدفوعة أو أرصدة مدفوعة أو ترقية تلقائية. إعداد spending budget أو تنبيه ليس بالضرورة قفل فوترة. المثبت يطلب منك تأكيد الخطة؛ لا يستطيع مفتاح استدلال عادي إثبات حالة الفوترة.

البرنامج لا يملك أي أداة لتفعيل الدفع أو ترقية الحساب. لكن إذا أعطيته مفتاح حساب مدفوع فقد يحاسبك المزود على الطلبات نفسها، حتى لو كانت تحت الحدود الداخلية. لذلك لا تستخدم حسابًا مدفوعًا لهذا الغرض. الحصص مشتركة مع بقية تطبيقات الحساب؛ إنشاء مفتاح جديد لا ينشئ حصة مجانية جديدة.

هذه حدود يفرضها البرنامج وليست وعدًا بأن المزود يمنحها لحسابك. حجز التوكنات محافظ ويشمل الطلبات الفاشلة؛ العدد الفعلي قد يكون أقل. عند 429 يحترم البرنامج Retry-After إن توفر ويؤجل الطلب؛ لا يغير الحساب أو يدفع لتجاوز الحد. عدادات البرنامج تبدأ يوم UTC بينما لدى Gemini إعادة ضبط مختلفة؛ أخطاء المزود تظل المرجع.

يمكنك خفض الحدود بعد مراجعة الحصص الفعلية. لا ترفعها عشوائيًا. تحقق شهريًا من خطة الحساب وتوافر النماذج، لأن الخدمات قد تغير حصصها أو توقف نموذجًا.

## كيف يعمل الوكيل

1. يقرأ RSS رسميًا من Windows وCloudflare وGoogle AI وNVIDIA. إذا فشل مصدر يتجاوزه. كل رابط يجب أن يكون HTTPS وعلى نطاق معتمد؛ التحويلات تُفحص أيضًا.
2. يختار أحدث خبر خلال 72 ساعة لم يُستخدم سابقًا. لا يدعي تحليل كل ترندات الإنترنت. المصدر التسويقي يُنسب كلامه للشركة.
3. يستخرج مقاطع دليل مرقمة من النص. الكاتب يستشهد بمعرفات المقاطع بدل اختراع اقتباس حرفي؛ المراجع يتحقق من دعمها للادعاءات.
4. يكتب نصًا عربيًا أصليًا، ويطبق اختبارات الأسماء/الأرقام/الطول/بنية البيانات ومراجعة نموذجية. يحصل المقال على محاولتي تصحيح كحد أقصى، وإلا يُحفظ للمراجعة.
5. ينشئ مسودة في تقنية 101. لا يعيد استخدام صورة اختبار فتاة الثمانينيات.
6. يولد صورة تعبيرية موضوعية، يفحصها بصريًا، يعيد التوليد مرة واحدة عند الرفض، ويحفظ وصفًا عربيًا وإشارة أنها مولدة.
7. يرفع الصورة ويربطها ويجدول المقال. يستخدم date_gmt ومكتبة timezone لضبط القاهرة.
8. يستأنف من الخطوة المحفوظة بعد انقطاع الشبكة أو إغلاق العملية. يعالج مقالًا واحدًا في كل تشغيل لمنع التنافس بين الطلبات؛ التشغيل التالي يتولى المقال الآخر أو المرحلة المتبقية.

مراجعة النماذج لا تضمن الحقيقة أو غياب تشوهات الصورة. المقالات الحساسة أو الخلافية تحتاج مراجعة بشرية. الحزمة مناسبة للخبر التقني المعتمد على إعلان رسمي؛ ليست بديلًا لتحقيق صحفي مستقل.

## الإصلاح والتحسين التلقائي

| الحالة | التصرف |
|---|---|
| انقطاع Groq أو محدوديته | تجربة Gemini المعتمد، أو تأجيل المهمة |
| انقطاع Gemini | بديل نصي عند توافره؛ تعليق الصور إن تعذر فحصها |

| صورة غير مناسبة | توليد جديد مرة واحدة، ثم تعليق المهمة |
| استجابة رفع/إنشاء مجهولة | البحث بالسلاج الثابت قبل محاولة الإنشاء لاحقًا |
| حصة مجانية مستنفدة | تأجيل دون ترقية أو شراء |
| 401/403 | إيقاف مؤقت للمزود وتسجيل مشكلة الاعتماد، دون تعطيل حماية الموقع |
| موعد فات | نقل عمل غير منشور إلى موعد مستقبلي متاح عند إمكان ذلك، دون نشر فوري |

ثلاث محاولات تشغيل فاشلة للمقال في اليوم كحد أقصى. طلبات الشبكة المؤجلة لا تدخل حلقات غير منتهية. المقال الذي فشل نهائيًا يبقى محفوظًا للمراجعة ولا يُنشر.

يفحص البرنامج آخر 30 مهمة: حالة المنشور، الصورة البارزة، تأخر النشر وحالة HTTP للصفحات المنشورة. يحفظ status-v2.json والسجلات. لا يفحص كل الروابط المضمنة أو كل المقالات القديمة بالموقع.

مرة في اليوم يفحص مادة منشورة واحدة من مواد الوكيل خلال آخر أسبوع. إذا تغيرت مقاطع المصدر، يحاول إعداد نسخة جديدة ومراجعتها وفحص الصورة. عند نجاحها يحدث المحتوى والملخص فقط ويحفظ نسخة قبل التعديل؛ يحتفظ بالرابط والعنوان وتاريخ النشر. إذا فشل أي شرط، يؤجل التحديث. هذا تحسين محدد بناء على مصدر جديد، وليس تدريبًا ذاتيًا للنموذج.

## نطاق الصلاحيات

الوكيل له أدوات مقيدة: قراءة المصادر، استدعاء النماذج المعتمدة، تعديل محتواه، رفع الصور، حفظ الحالة، وإعادة المحاولة. لا توجد أداة shell عامة ولا أداة تعديل كود WordPress أو تفعيل الدفع أو حذف المحتوى جماعيًا. إعدادات المواعيد والتصنيف ليست بيد النموذج.

الإصلاح التشغيلي التلقائي لا يضمن إصلاح كل عيب برمجي جديد. أعطال الكود غير المتوقعة تُسجل وتحتاج تصحيح إصدار. لا يُمنح النموذج صلاحية تعديل نفسه مباشرة في الإنتاج؛ تغيير برمجي مستقبلي يحتاج نسخة مع اختبارات وتراجع. هذه الحزمة لا تحتوي وكيل تطوير يعمل ذاتيًا لإنشاء وترقية كوده.

## المتابعة دون أوامر متكررة

- START.cmd: إعداد مرة واحدة وتشغيل الجدولة.
- STATUS.cmd: عرض الحالة والأخطاء واستهلاك اليوم.
- PAUSE.cmd: إيقاف المهام المستقبلية. لا يلغي المنشورات المجدولة بالفعل في WordPress.

## إصلاح حجم الطلبات وفترات الانتظار

تحديث 5 نوفمبر: تُراجع المقالات في حزم صغيرة (العنوان والملخص ثم الفقرات مع مقاطع الدليل الداعمة) بدل إرسال المقال والمصدر كاملين في كل مراجعة. لا يتم إسقاط فقرات المقال من التحقق. تحفظ نتيجة كل حزمة ناجحة للاستئناف بعد انقطاع مزود الخدمة. التصحيح يعيد كتابة المقال من الدليل والملاحظات دون تكرار النسخة السابقة كاملة في الطلب.

حد الطلب المحافظ لـGroq لم يُرفع. أصبح حد مخرجات المراجعة 800 وحد الكتابة 3200، ومقاطع المصدر الجديدة محدودة بالبايتات لمراعاة العربية وUnicode. انتظار المزود أو الحصة لا يحتسب فشلًا في جودة المقال؛ تبقى ميزانيات API اليومية وحدود محاولات التصحيح قائمة. حالة المهمة تعرض retry_at بتوقيت القاهرة وعدد المحاولات الفاشلة، وملف status-v2.json يعرض فترات انتظار المزودين أيضًا.

عند أول تشغيل لهذا التحديث تُستأنف المهام غير المنتهية بعد إزالة عدادات فشل الإصدار السابق على مستوى المهمة فقط. لا يحذف سجل الاستهلاك ولا يلغي انتظار المزود ولا يعيد ضبط الحصص. معرّفات المسودات والصور محفوظة. المثبت يوقف مهمة المشروع السابقة أثناء التحديث ثم يعيد تسجيلها بعد نجاح الفحص.

تمت إضافة اختبارات لطلب عربي كبير، تقسيمه دون إسقاط نصه، بديل Groq عند خطأ Gemini 5xx، واستئناف حزم المراجعة وعدم احتساب الانتظار فشلًا تحريريًا. الاختبارات محاكاة محلية، ولا تثبت توافر مزود خارجي وقت التشغيل.
